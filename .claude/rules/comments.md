# Комментарии

Правило делит комментарии надвое.

**Docstring на публичном идентификаторе — обязателен** (ruff `D100–D106` в гейте, аналог `revive.exported`): одна строка, говорит, что это и чего от него ждать. Это контракт для читателя `help()`/IDE, а не «нарратив». Больше одной строки уместно, только когда контракт того требует: набор исходов/исключений, что обязан положить в контейнер caller, ограничение, о котором иначе узнают в проде. Package-doc (`__init__.py`) — 1–3 строки: что за кит и какие сигналы эмитит; детали — в `README.md` кита.

**Всё остальное — по умолчанию не писать.** Внутри функций хорошее имя уже объясняет WHAT. Комментарий допустим, только если без него читатель не догадается о **WHY** — скрытая инварианта, неочевидное ограничение, workaround под конкретный баг, поведение которое удивит.

## Запрещено

- **Restate WHAT.** `"""Возвращает пользователя по id."""` над `get_user_by_id` — формально docstring, но пустой: скажи, что бывает при отсутствии (`NotFoundError`), или ничего сверх имени.
- **Narration.** Многострочный пересказ "сначала делаем X, потом Y, наконец Z". Код это и так показывает.
- **Архитектурные эссе в module docstring.** Не описывай pattern/принципы рядом с реализацией — это место для `README.md` кита или `CLAUDE.md`. Особенно касается `module.py`.
- **Tombstones.** `# removed XXX`, `# was using Y before` — нет, для этого есть git log.
- **Reference to current task/PR.** `# added for X flow`, `# fix for issue #123` — это в commit message, не в коде.
- **Flavor commentary.** Художественный пересказ того, что и так видно.
- **TODO без контекста.** `# TODO: fix this` — бесполезно. Оставляешь TODO — дай ticket/owner/condition.
- **Section dividers.** `# ===== Helpers =====` — модули и так структурированы.

## Допустимо внутри функции (одна короткая строка)

- WHY-инвариант: `# Протокол, а не ABC: чужой класс подходит структурно.`
- Workaround: `# asyncpg отдаёт jsonb строкой; декодируем сами до появления кодека в пуле.`
- Сюрпризное поведение: `# ОБЯЗАН вызываться до start — регистрирует роуты в приложении.`
- Хитрая константа: `# 90s = idle-таймаут upstream nginx − 10s запаса.`

## Чек

Комментарий внутри функции длиннее **одной строки** — почти наверняка лишний: вырази именем/структурой, а «почему так» — в `README.md`, не в `.py`. Docstring длиннее одной строки — проверь, что каждая следующая строка добавляет контракт (исход, требование к контейнеру, ограничение), а не пересказ. После правки глянь diff: добавленный комментарий объясняет невидимое из кода? Нет — удали.
