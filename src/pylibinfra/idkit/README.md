# idkit

Генерация и проверка внутренних идентификаторов. `new_v7` отдаёт UUID v7
(RFC 9562) строкой — time-sortable id, у которого старшие биты несут unix-ms. В
отличие от случайного v4, такие id монотонно растут во времени и дают локальность
в B-tree индексах (меньше фрагментации страниц для PK). `validate`/`is_v7`
проверяют строку из внешнего мира. Только stdlib, без I/O.

## Импорт

```python
from pylibinfra import idkit
```

## Быстрый старт

```python
key = idkit.new_v7()  # "0190e8a1-1c2d-7e3f-8a4b-5c6d7e8f9a0b"

# production-seam для конструктора, принимающего id_gen: Callable[[], str]
entity = Entity.new(account_id, id_gen=idkit.new_v7)

# валидация id, пришедшего из запроса/события
try:
    idkit.validate(payload["entity_id"])
except idkit.InvalidIDError as exc:
    raise BadRequest(str(exc)) from exc
```

## Observability

Кит **ничего не эмитит**: ни метрик, ни спанов, ни логов.

## API

```python
def new_v7() -> str
def validate(value: str) -> None      # InvalidIDError
def is_v7(value: str) -> bool
class InvalidIDError(ValueError)      # .value
```

| Символ | Роль |
|---|---|
| `new_v7()` | Новый id: канонический UUID v7 строкой |
| `validate(s)` | Ничего, если `s` — канонический UUID (любой версии); иначе `InvalidIDError` |
| `is_v7(s)` | `True`, если `s` — канонический UUID версии 7 с вариантом RFC 4122, то есть мог быть выдан `new_v7` |
| `InvalidIDError` | Подкласс `ValueError` с полем `value` |

**Канонический вид** — ровно 36 символов, hex в нижнем регистре, группы
`8-4-4-4-12` через дефисы. `uuid.UUID(...)` из stdlib шире: он принимает ещё
URN-форму, фигурные скобки, 32 hex без дефисов и верхний регистр. `validate`
такие формы отвергает: у сервисов stit id хранится и передаётся ровно в том
виде, в каком его отдал `new_v7`, поэтому «почти правильный» id — ошибка входа,
а не значение для нормализации.

## Инварианты и подводные камни

- **В пределах процесса id строго возрастают.** Под глобальной блокировкой кит
  держит последнюю выданную миллисекунду и 12-битный sub-ms счётчик (`rand_a`):
  в одной миллисекунде счётчик растёт, при переполнении метка сдвигается на
  1 мс, при откате системных часов выдача продолжается от последней метки.
  Поэтому лексикографический порядок строк, выданных одним процессом, совпадает
  с порядком вызовов — в том числе внутри одной миллисекунды.
- **Между процессами и узлами порядок только по миллисекундам.** Счётчик
  локален для процесса; `ORDER BY id` — про порядок вставки, а не про
  глобальную истину времени.
- **Случайность — `os.urandom`** (62 бита `rand_b`); её отказ — невосстановимое
  состояние процесса, исключение не перехватывается.
- **Только v7.** Нужен v4 — `uuid.uuid4()` из stdlib; кит намеренно узкий.
- **`validate` не проверяет версию.** Это проверка формата; «это именно наш
  id-формат» — `is_v7`.
