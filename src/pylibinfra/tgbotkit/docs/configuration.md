# Конфигурация tgbotkit

## Config (ENV)

`tgbotkit.Config` — публичный env-контракт бота. Читается `new_config()` либо через
`config.load(Config, *sources)`.

> **Public API.** Имена полей и их `validation_alias` — часть стабильного контракта
> (корневой README § Стабильность API). Менять их = breaking change.

Окружение читается только по алиасу (`configkit.KitSettings`): переменная с именем поля
(`mode`) конфиг не заполняет. Пустая переменная равносильна незаданной — берётся дефолт.
Конфиг заморожен после валидации.

| Env | Поле | Тип | Default | Назначение / правило валидации |
|---|---|---|---|---|
| `BOT_TOKEN` | `token` | `SecretStr` | — | Токен Bot API. **Обязателен**; формат `<bot_id>:<secret>` проверяется на старте. Значение не попадает в текст ошибки, `repr` и логи |
| `BOT_MODE` | `mode` | `polling` \| `webhook` | `polling` | Как принимать апдейты. Иное значение — `ConfigError` |
| `BOT_PARSE_MODE` | `parse_mode` | `HTML` \| `MarkdownV2` \| `Markdown` \| `""` | `HTML` | Разметка по умолчанию у всех исходящих сообщений. Пустая строка — без разметки. Иное значение — `ConfigError` (иначе Telegram отбивал бы каждое сообщение `400`) |
| `BOT_API_TIMEOUT` | `api_timeout` | `float`, секунды | `60` | Таймаут одного вызова Bot API (HTTP-сессия aiogram). `> 0` |
| `BOT_SHUTDOWN_TIMEOUT` | `shutdown_timeout` | `float`, секунды | `10` | Общий бюджет дренажа фоновых подписок и остановки опроса при выключении. `>= 0`; исчерпан — предупреждение в лог и отмена |
| `BOT_DEDUP_ENABLED` | `dedup_enabled` | `bool` | `true` | Дедуп апдейтов по `update_id` в общем Redis |
| `BOT_DEDUP_TTL` | `dedup_ttl` | `float`, секунды | `600` | Окно, в котором повтор `update_id` считается дублем. `> 0`; округляется вверх до секунды (`EX` мельче не умеет) |
| `BOT_THROTTLE_RPS` | `throttle_rps` | `int`, апдейтов/с | `0` | Лимит входящих апдейтов на пользователя. `0` — выключен, `>= 0` |
| `BOT_STATE_TTL` | `state_ttl` | `int`, секунды | `0` | TTL FSM-состояния и данных диалога в Redis. `0` — без срока (ключи копятся), `>= 0` |
| `BOT_FLOOD_ENABLED` | `flood_enabled` | `bool` | `true` | Session-middleware исходящих: rate-limit, порядок в чате, ретрай `429` |
| `BOT_RATE_GLOBAL` | `rate_global` | `float`, сообщений/с | `30` | Глобальный лимит исходящих (лимит Telegram). `0` — без лимита, `>= 0` |
| `BOT_RATE_PER_CHAT` | `rate_per_chat` | `float`, сообщений/с | `1` | Лимит исходящих в один чат. `0` — без лимита, `>= 0` |
| `BOT_RATE_MAX_WAIT` | `rate_max_wait` | `float`, секунды | `60` | Потолок ожидания одним вызовом: слота GCRA (сверх него вызов уходит с предупреждением) и `retry_after` из `429` (сверх него исключение уходит вызывающему). `> 0` |
| `BOT_RETRY_AFTER_ATTEMPTS` | `retry_after_attempts` | `int` | `3` | Сколько раз повторить вызов после `429`. `>= 1`; `1` — без повторов |
| `BOT_WEBHOOK_PATH` | `webhook_path` | `str` | `/tg/webhook` | Путь POST-роута вебхука. Обязан начинаться с `/` |
| `BOT_WEBHOOK_BASE_URL` | `webhook_base_url` | `str` | `""` | Внешняя база URL бота. В webhook-режиме обязательна и обязана быть `https://` |
| `BOT_WEBHOOK_SECRET` | `webhook_secret` | `SecretStr` | `""` | Секрет заголовка `X-Telegram-Bot-Api-Secret-Token`. В webhook-режиме обязателен; `1..256` символов `A-Z a-z 0-9 _ -` |
| `BOT_DROP_PENDING` | `drop_pending_updates` | `bool` | `false` | Отбросить накопленные апдейты при старте |

## I18nConfig (ENV)

Вложен в `Config` как поле `i18n`; читает окружение сам.

| Env | Поле | Тип | Default | Назначение / правило валидации |
|---|---|---|---|---|
| `BOT_I18N_PATH` | `locales_dir` | `str` | `""` | Корень каталогов локалей (`<path>/<locale>/*.ftl`). Пусто — i18n выключен, виджеты рендерят сам ключ. Непустой обязан существовать и содержать каталог дефолтной локали |
| `BOT_I18N_DEFAULT_LOCALE` | `default_locale` | `str` | `en` | Локаль, в которую резолвится неизвестный `language_code` и из которой берётся недостающий ключ. Непустая |
| `BOT_I18N_RESOURCES` | `resources` | `list[str]`, CSV | `main.ftl` | Имена `.ftl`-файлов внутри каждой локали. Список непустой |

Поле называется `locales_dir`, а не `path`, намеренно: имя `path` из окружения совпало бы с
системным `PATH`, если источник когда-нибудь перестанет быть строгим.

## Правила валидации

`new_config()` и прямой `Config(...)` валидируют одинаково; `new_config()` поднимает
`tgbotkit.ConfigError`, прямой конструктор — pydantic `ValidationError` (тоже `ValueError`).

| Правило | Почему |
|---|---|
| `BOT_TOKEN` непустой и формата `<bot_id>:<secret>` | Бот без валидного токена не сделает ни одного вызова; забытая переменная обязана валить старт, а не первый апдейт |
| `BOT_PARSE_MODE` — из фиксированного набора | Опечатка (`html`) означала бы `400` на каждом сообщении и молчащего бота |
| Таймауты и TTL `> 0`, лимиты и окна `>= 0` | Нулевой таймаут Bot API означал бы мгновенный отказ, отрицательный лимит — отбитые сообщения |
| `BOT_RETRY_AFTER_ATTEMPTS >= 1` | Ноль попыток — это «не отправлять вовсе» |
| `BOT_WEBHOOK_PATH` начинается с `/` | Иначе роут не совпал бы с URL, который получил Telegram |
| В webhook-режиме `BOT_WEBHOOK_BASE_URL` — `https://` | Telegram ставит вебхук только на TLS |
| В webhook-режиме `BOT_WEBHOOK_SECRET` непустой | Гейт вебхука fail-closed: с пустым секретом он отбивает все апдейты, и бот выглядит живым, но немым |
| `BOT_I18N_PATH` существует и содержит каталог дефолтной локали | Иначе fluent молча рендерит каждый ключ самим собой — ошибка видна только глазами в проде |

Нулевой конфиг тут не бывает: без `BOT_TOKEN` он отвергается. Всё остальное имеет безопасные
дефолты — polling, дедуп включён, лимиты Telegram выставлены, вебхук выключен.

## Конфиги соседей, которые нужны боту

| Кит | ENV | Зачем боту |
|---|---|---|
| `cachekit` | `REDIS_URL`, `REDIS_*` | FSM-состояние, дедуп, лимиты, event-isolation диалогов |
| `httpkit` | `HTTP_ADDR`, `HTTP_*` | Порт `/health` + `/ready`, а в webhook-режиме — приём апдейтов |
| `logkit` | `LOG_*` | Единый формат записей; `capture_stdlib` уводит туда же логи aiogram и uvicorn |
| `natskit` | `NATS_URL`, `NATS_JS_*` | Только если бот слушает события бэкенда (`NotifierBundle`) |

## Длительности

Все длительности — секунды `float` (Go-строки вида `15m` не парсятся). Целочисленные секунды
(`BOT_STATE_TTL`) остаются `int`: они уезжают в TTL Redis как есть.
